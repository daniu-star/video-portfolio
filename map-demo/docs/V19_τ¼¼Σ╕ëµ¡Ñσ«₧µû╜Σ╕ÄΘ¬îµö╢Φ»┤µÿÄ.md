# 贵州3D交互地图游戏 V19 · 第三步实施与验收

版本 2026-10-28。改造基线 V18 第二步完整工程。本轮**只改造中国天眼三角色、双时代的故事与互动机制**，保留前两阶段入口、阶段状态机、证据核查、结果页、草稿存储，以及桥梁与货车游戏原有代码。

## 一、本轮解决的主要问题

| 原有问题 | 已落地的改变 | 验证方式 |
| --- | --- | --- |
| 三种身份主要区别在题目文字 | 为科研人员、建设者、公众建立不同委托方、现场工作台与成果名称 | 六组角色时代分别加载、操作、归档 |
| 建设期2011年也画出完整反射面 | 建设任务从洼地轮廓、施工框架与逐步安装的示意状态展开，运行期显示完整装置轮廓 | 浏览器画面截图对照 |
| 点击阅读资料即可完成许多操作 | 新增角色现场操作门槛，完成证据后仍需操作对象、校验或记录，才可进入判断 | 未完成实操时阻止进入判断的反向测试 |
| 运行时代只说“已完成N项” | 读取同一角色建设期的具体参数、构件记录或地方议题，并要求在相关任务中打开核查 | 跨时代存档检查，独立进入运行期使用明示的教学档案样本 |
| 三条身份线从不交叉 | 可折叠资料交换栏读取其他身份已经完成的真实本机游戏记录 | 其他身份无记录时不编造已完成资料 |
| 完成的任务只是选择题列表 | 每关按具体的观察、校验、对比等工作生成带类型的学习成果 | 18条记录有 `output.v19` 结构化成果 |
| 新的操作可能导致旧存档无法清空 | 游戏中心清除档案操作同时清理新增现场状态 | 代码检查 |

## 二、六条连续的故事线

三角色围绕大窝凼建设、调试、长期运行及其与地方生活的联系，处于不同工作位置，所有人物委托为教学合成，不是实地受访者原话。

| 角色 | 建设时期2011—2016 | 运行时期2020起 | 带入下一时期的具体记录 |
| --- | --- | --- | --- |
| 科研人员 | 台址条件观察、主动反射面与馈源协同、工程读数复核 | 观测准备、合成波形筛选、候选信号复核 | 构件与馈源协同的模拟校验参数、台址条件 |
| 工程建设者 | 部件识读、模拟安装、异常报告 | 设备巡检、维护排期、工程科普 | 安装部件与测试结果 |
| 周边居民 | 生活空间标记、社区议题、历史与未核实记录区分 | 合规参观、电磁环境对照、负责的科学讲解 | 居住、通行、生产的关注议题 |

每关以“谁委托—发生什么—实际操作—获得什么—下一步为何需要”组织。`assets/js/fast/v19-story-world.js` 的 `STORY` 包含18个任务的字段，其 `kind` 指定不同互动形态，包括场景观察、构件识别、对比、情境切换、波形标记、装配校验及文本表达。

## 三、游戏规则与数据结构

新层依托 V18 的 `collect → decision → feedback` 阶段管理。在 `collect` 阶段对每个任务补充角色现场操作要求；若未完成，`check` 会明确提示遗漏。正确回答后保存 `output.v19`，记录互动类型、所选项、具体标签、档案核对状态和成果名。状态保存在 `guizhou-games-v16` 的 `fastV19` 节点下，以 `角色.时期.关卡编号` 为索引。任务完成后，成果写入 `fast` 对应记录并移除当前临时现场状态。

建设期向运行期传递 `output.sliders` 或 `output.v19`，作为运行期回看内容。它不改变历史事实，不把游戏参数当作真实FAST施工或观测参数。

任何玩家都可以直接进入运行期。若未完成建设期，界面会明确提示使用“教学档案样本”，并要求玩家实际打开核对，不能伪称玩家曾在建设期留下记录。

三角色的交叉资料栏仅读取当前浏览器中已有的其他角色成果，且为可选的辅助资料，不强迫玩家依次完成六条故事线。

## 四、科学、历史与伦理边界

- 建设时期模型的进度变化是**教学时序模型**，并非FAST工程在指定年月的实测三维重建。项目历史事实以中国科学院国家天文台公开资料为依据。2011年开工、2016年落成、2020年通过国家验收。
- FAST反射面为固定的500米球面结构，观测时局部主动调形并与馈源定位系统协同。双滑块是抽象教学参数，没有真实方位角、测量或施工单位。
- 运行期电磁环境分级使用2019年版本的贵州省相关保护办法。不得把2019年具体管理条例描述为2011年的同时期法规。
- 社区生活、咨询、交流与人物委托均为教学合成。不同居民的经历、搬迁状况与具体补偿不能由模拟地图推断。游戏没有使用任何未经核验的田野引语。
- 真实参观资格、区域开放、设备使用仍以现行管理规定和现场工作人员要求为准。

## 五、测试情况

- 使用 Chromium 的本地 HTML 内联方式执行六组角色时代自动化检查，全部18项任务通过“现场操作—证据—判断—反馈—保存”流程，并生成对应成果记录。测试并非18位真人体验，采用脚本控制游戏事件并检查状态。
- 单独验证现场操作缺失时不能通关、取得必要操作后可以判断、无建设期记录时使用教学档案样本、运行期档案未核对时不能提交等失败与恢复路径。
- 页面脚本检查未发现未捕获异常，390像素移动端在测试页面中无横向溢出。
- 对比检查建设初期与运行时期的模型轮廓，并输出桌面与移动端截图。
- 源码可由本地静态服务器运行，单文件体验版以脚本内联生成。由于自动化运行环境的浏览器网络策略限制，完整工程在本轮未通过实时HTTP托管的端到端测试，需在真实设备进一步验收。

## 六、仍需继续改造

本轮改善了角色差异与因果链，但3D仍为基于Canvas绘制的概念透视模型，未接入精确工程几何、实景或真实测绘坐标。部分关卡依然需要额外点击证据卡和完成判断，操作节奏与文案密度仍可减负。第五步应重新统一信息架构、字号、色彩、按钮样式、移动端阅读路径，并进行零基础真实用户测试。

第四步聚焦花江峡谷大桥与公路货车两款游戏，重建驾驶、路线、货运任务和到站观察的行动因果。
