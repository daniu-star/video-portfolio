# V32 三维驾驶场景升级与验收边界

## 本轮工作范围

本轮以 V31 为基线，针对驾驶体验中几何不统一的问题，新增 `assets/js/scene/v32-drive-world.js`。在支持 WebGL2 的环境中，该模块与原有地形、水面使用同一个深度缓冲区，重新绘制连续的道路结构、梁体、主塔、主缆、吊索、护栏及动态汽车。材质采用程序化纹理、太阳方向光、环境补光、镜面高光、远景雾化。新增远景天空着色及湿滑道路粗糙度差异。

原 Canvas2D 绘制保持原样，WebGL2 不可用时自动回退。原始地形数据、数据库、配置、FAST游戏、花江游船、双工程调查均保留。

## 图形技术边界

- V32 的 GPU 场景是真正的 WebGL2 深度测试三维几何。它对遮挡顺序和道路纵深具有潜在提升。
- 地形仍基于项目原来的概念高程采样，未经实测DEM或高分辨率影像验证。
- 当前桥梁几何按教学尺度构造，与真实桥梁 BIM / CAD 不一致。
- 车辆采用原创程序化通用汽车几何，未获得任何真实车型制造商CAD或扫描资产。
- 车辆运动继续采用 V31 的简化受力模型。没有刚体碰撞、轮胎接地接触求解，也没有经过标定的真实悬架参数。
- `assets/models` 中的两份 GLB 是从程序化源导出的编辑参考资产。网页运行时直接生成几何，不会读取它们。
- GPU阴影贴图、环境反射探针、真实摄影测量纹理、LOD流式地形、时变雨雾和影视级材质仍未实现。

## 测试证据

- JavaScript 语法检查通过，HTML 和CSS/JS资源在内联浏览器加载时无未捕获异常。
- 通过模拟 WebGL2 接口执行顶点数据生成、结构完整性检查及缓存验证。该模拟不等于着色器编译成功。
- 道路/桥梁几何约 4 万个三角形，车辆网格约 360 个三角形，GLB 文件能够由 trimesh 重新读取。
- Chromium 1280×800、390×844 的 Canvas 兼容路径启动、加速、刹车、视角切换无脚本异常及横向溢出。
- 当前测试机 WebGL2 上下文创建失败。**本轮没有真实GPU渲染截图、实时帧率或显存测试，也不能保证 GPU管线在所有设备上正常运行。**

## 真实写实资产与数据的进入条件

1. 获取花江峡谷与FAST区域有明确许可证的高程DEM，保留坐标系、分辨率、水平垂直精度和来源元数据。
2. 收集合法授权的正射影像或摄影测量资产，严禁把生成纹理称为实地测量。
3. 桥塔、主缆、吊索、桥面、支座和结构比例应由 BIM / 竣工图和公开工程参数核对。
4. 车辆需要经过许可的高精度外观模型、LOD层级、PBR材质、底盘及可动轮组。经专门资产审核后再替换当前网格。
5. 在具备 WebGL2 的真实桌面GPU设备进行基线测试，包括1080p最小/平均帧率、着色器编译、深度遮挡、远近裁剪、阴影、逐帧稳定性以及设备兼容性。
6. 对主要镜头形成生产相机截图、几何核对记录与游戏可用性验收。外部付费生成平台不得在未获得单次预算审批前使用。

## Game Room制作闸门

本工程现阶段属于游戏内开放场景的程序化预览，尚未取得独立Function、Form和Runtime人工验收。GLB静态读取只证明文件和三角面存在；不证明拓扑、真实比例、GPU导入或视觉精度满足最终制作标准。
