# 贵州双工程交互地图｜从首次访问者视角进行的页面审计与修复

> 测试版本：用户此前收到的 `贵州3D交互地图_V7_第四阶段_FAST科普游戏_完整工程.zip`。本报告不是新功能概念任务书，而是对该 ZIP 展开的工程所做的实际代码修改、Chromium 逐步操作与待办记录。
>
> 测试日期：2026-10-22。当前修复分支：`V7 UX Repair / First-Visitor QA`。

## 0. 真实性与测试边界（先说明清楚）

**实际执行的项目内容：** 解压第四阶段交付包，以包内 `index.html`、CSS、JS 与 `database.bundle.js` 为输入；在 Chromium 中将**这份 HTML 连同本地脚本、样式原文内联装载**，随后由 Playwright 像用户一样按顺序点击按钮、切换场景、完成 FAST 三关、进入桥梁模拟驾驶、查看数据、退出并再次操作，生成浏览器渲染截图及 JSON 日志。不是图像生成器的效果图。

**没有执行成功的测试：** 此运行环境的 Chromium 被管理员策略阻止直接访问 `file://`、`http://127.0.0.1` 页面，因而不能声称在此完成了“用户双击 `index.html` / 本地 HTTP 服务 / 正式部署 URL”的验证。内联测试保持 DOM、JS 和 CSS 逻辑，但不涵盖真实网络取图、SDK 服务鉴权、瓦片渲染与跨域来源控制。工程附有 `qa/real_browser_journey.py`，可在具备正常浏览器环境的机器上指定 `JOURNEY_URL` 重跑外部访问流程。**以下「浏览器通过」仅指内联 DOM 真实 Chromium 操作。**

**未经验证不能说已完成：** Google / 高德真实 3D 地形加载；现实中任何单栋建筑影像与 3D 体块的一一对应；真实道路中线、桥塔与桥面结构尺寸、可驾路线合法性。最新数据库 `media_assets` 与 `media_bindings` 均为零。不能用“地图来源链接存在”代替“现场照片已嵌入本地 HTML”。

## 1. 首屏：看到了气氛，但不知道“下一步”是什么

**原表现（已由结构与交互代码确认）：** 首屏的唯一明显按钮是 `#enterMapBtn`。进入后的导航区域同时出现空间模式、缩略地图、资料卡、时间轴、故事、数据库和视角控制，缺乏简单任务选择。点击进入后有约 1.12 秒动画延迟，原按钮文字不会及时响应；操作迟疑时用户可能认为按钮不灵。

**修复：** `assets/js/app.js` 在点击后立即把按钮文字改成“地图正在打开…”，禁用重复点击；地图进入后弹出 `#visitorGuide`，用四个完整路径说明：①天眼信号守护，②花江模拟穿越，③真实地点摄影，④自由探索。每个选项的按钮事件都接到实际项目状态机，支持跳过和从地图重开。引导信息明确说明地形、道路为示意，以及真实地图需要密钥。

**验收方式：** 浏览器脚本验证首次引导显示、跳过和继续操作。截图：`qa/journey/desktop_02_03_onboarding_visible.png`、`mobile_19_03_onboarding_visible.png`。这是真实浏览器渲染内容；不是“已上线到互联网”。

## 2. 地图中央：多个入口与节点、资料卡相互遮挡

**原表现：** `fast-quick` 与 `fast-pulse` 两个按钮面向同一个 FAST 游戏，位置各自独立；地图节点、已打开的 `node-legend`、Inspector 资料卡和左侧快捷按钮占用相同视野。旧截图可以看到“启动天眼”与核心设施标签挤在一处。首屏缺少统一的操作序列。

**修复：** 三类常用操作合并为 `#journeyBar`（因场景切换显示“桥梁体验”或“天眼游戏”），加入“现场照片”“玩法指南”；取消重复 FAST 浮动入口，保留桥梁场景的概念穿越提示；进入驾驶或 FAST 模态后让条形入口退出视野。移动端使入口栏可横向滑动而不覆盖整块地图。

**限制：** 原先的 Canvas 2D 场景仍能绘制大量标签，在某些相机角度可能叠加。彻底解决需要节点标签避让算法和图层优先级重构；本轮主要修复操作入口的遮挡。

## 3. 手机浏览：顶部按钮堆叠，部分功能像“丢失”

**原表现：** 移动端 CSS 虽然缩短了按钮文字，但仍将 Story、Data、Theme 和地图控制一起放入顶部；`@media(max-width:960px)` 使数据库左侧表选择导航 `display:none`，因此小屏用户即使打开数据库也无法靠原菜单切换数据表。部分浮动按钮会盖在地图热点和节点档案上。

**修复：** 小屏顶部保留场景选择、地图、照片和帮助，次级操作收入 `#mobileMoreMenu`，并确保这个按钮**在 `.theme-menu` 外部**。该处是本次实际浏览器回归新发现的真实缺陷：初次改版因 HTML 闭合位置不当，菜单按钮被一起隐藏；经失败日志定位、调整 HTML 嵌套后重新跑通。数据弹窗添加 `#mobileDbSelect`，使手机用户可实际切换道路、节点、建筑、指标等表。

**浏览器证据：** 改动后的自动化在 390×844 中从“更多”进入数据页，选择道路表，再关闭；接着通过“更多”启动和暂停故事。页面的 `scrollWidth` 与视口宽度一致（390px），未检测到根文档横向溢出。但这不等于任意字体缩放下均无遮挡。

## 4. 地点资料：移动端大面积遮挡地图

**原表现：** `.inspector` 在窄屏仍占相当大的可视高度，底部另有 `timeline`、`leftRail`，空间信息阅读与地图探索容易互相竞争。节点资料同时显示在多个面板中，信息重复。

**修复：** 增加 `#inspectorToggle`，手机初始使用较矮的收起状态；用户点击地图节点时自动展开详情。超窄屏关闭重复的 `node-legend` 浮层，改以 Inspector 为主要读取渠道。

**本次抓出的实际 JavaScript 错误：** 修复过程中错误使用 `getElementById('inspectorToggle span')`，在移动端启动时报 `TypeError: Cannot set properties of null (setting 'textContent')`，后来用错误堆栈定位到 `visitor-journey.js -> syncInspector`，改成 `getElementById('inspectorToggle').querySelector('span')`；再次启动测试不再出现该错误。该发现证明本轮测试不是简单检查 DOM 是否存在。

## 5. “现场实景”：有照片按钮，却未必真的有照片

**原表现：** 工程本地没有经过授权并绑定的实景图像。`geo-provider.js` 只有两组 Wikimedia Commons 在线链接。离线打开 `index.html` 或外网被限制时，图片区可能空白。用户把“能点击照片”理解为“本地已嵌入真实照片”，这是此前交付描述不够准确的问题。

**修复：** 新增 `#photoLoadState`：默认显示“正在读取”；只有 `img.onload` 成功后才能标记“已加载公开实景摄影”；`img.onerror` 则显示明确失败原因，并保持摄影者、日期、许可和原始版权链接。既不把场景建模截图称为摄影，也不把一个地区的照片冒充特定建筑的照片。

**仍未修复：** 没有真正将获授权的照片文件打包为本地离线资源，因此在断网场景下无法保证显示真实照片。后续需要明确授权、拍摄位置和使用范围后，将照片下载入 `assets/media/approved/` 并写入 `media_assets`、`media_bindings`。这不是靠改 CSS 能解决的问题。

**版权来源核查：** FAST 摄影作者 SCJiang 的作品为 CC BY-SA 4.0；花江大桥摄影作者 Glabb 的作品为 CC BY-SA 3.0。仅记录来源不代表文件已经被合法下载到工程内。

## 6. “真实 3D 地图”：没有密钥时不能把模拟地形说成真实地形

**原表现：** `#geoOpen` 调用高德 / Google SDK 接口，但项目不包含密钥、合法瓦片和真实地形数据。真实地图缺失时，旧 Canvas 仍会显示示意地貌，可能造成“真实数据已载入”的错觉。真实 SDK 初始化后如果底图区域没有瓦片，当前逻辑仍可能存在空白/黑屏风险，尚缺瓦片覆盖层级的端到端验收。

**修复：** 入口改称“在线 3D 地图（需密钥）”，新手引导和设置弹窗明确说明授权前提和概念场景的区别；无密钥提交的表单错误经过 Chromium 操作验证，会阻止加载请求并保留概念地图。

**仍未修复：** 真实高程、地形瓦片、街景、Google 3D 摄影级覆盖、Geo/地图坐标一致性及服务器鉴权。要在部署域名和已授权 Key 下验证加载事件、瓦片失败提示与回退动作，不能用 Mock 或离线加载测试替代。

## 7. 花江模拟驾驶：入口难找、左右观察不足、视角变化不明显

**原表现：** `#driveLookLeft`、`#driveLookRight` 在 `drive-v7.css` 的 `max-width:600px` 条件下被直接 `display:none`；控制器原 `glance()` 只增加约 ±0.33 偏移，又在每帧以衰减系数迅速恢复，按一下效果很容易错过。四种视角切换虽在控制器代码中存在，但没有形成足够清晰的游戏操作引导。

**修复：** 手机上恢复“看左侧 / 看右侧”两按钮与短提示，明确不控制车辆转向；左右观察增加到约 ±0.95 的镜头偏移，保持约 2.1 秒再自动回正；四种镜头按钮继续保留，桥梁引导选择路线时增加玩法说明。实际浏览器自动切换 `passenger`、`follow`，点击“右看”，检查控制器值大于 0，随后暂停与退出。

**仍未修复：** 桥梁道路和桥塔仍然是程序化示意。没有高精道路中线、经核准桥塔点位、真实桥面剖面、护栏模型与近景纹理。界面能切视角，并不意味着工程场景已获得实景级复原。

## 8. FAST 科普游戏：会操作，但不知道每一步和科研的关系

**原表现：** 游戏大体分为关发射源、答宁静区情境和识别波形三阶段，但用户如果直接被带入第一关，可能不清楚这些操作与 FAST 射电观测的科学逻辑有什么关系。手机宽度小于 420px 时，旧 CSS 将第二关地图 `.fast-zone-map` 完全隐藏——这是实质性的图文断裂：让人做空间判断，却不展示空间图。

**修复：** 新手路线卡明确给出“关干扰 → 理解分区 → 挑候选”的学习逻辑；第二关在手机端恢复紧凑分区图，并增加“0—5km / 5—10km / 10—30km”文字带，防止只有缩小的图圈没有可读解释。FAST 游戏打开时暂停背景三维 Canvas 的高成本连续渲染，减少全屏游戏和后台地图重复绘制。

**实际浏览器操作：** 进入介绍页，启动第一关，尝试未关闭就提交并读取提示，依次关闭三个发射源；回答三个分区情境；最后选择候选波形并提交，进入完成页面，然后退出回地图。这些点击运行成功。**但没有被本轮证实的项目是：**不同学生真实理解程度、长期知识记忆、所有设备上的帧率和教育效果。

## 9. 数据库与故事模式：电脑能用，不代表手机能用

**原表现：** 原来的数据库在桌面通过右上角 Data 打开；手机可能因同一按钮拥挤被隐藏、或左右侧边导航不见而无法使用。Story 的图标“▶”也没有明确说明是一段自动播放故事，容易与桥梁驾驶冲突。

**修复：** 在移动端“更多”菜单中提供“自动故事 / 查看数据 / 更换主题 / 操作说明”，全部连接原有功能。数据库增加移动端表选择器。桌面仍保留常用按钮，不强迫所有人使用手机菜单。

## 10. 运行错误与黑屏：只能标记范围，不可凭无报错宣布全面通过

本次 Chromium 内联加载页面后，执行了点击、弹窗、切换和游戏关卡。发现并修复了一个移动端启动时真正的 `TypeError`。对于用户提出的“选项出现黑屏”，测试脚本将记录当前环境能观察到的脚本错误与渲染尺寸，但 **不能证明** 真实浏览器通过 file:// 访问、Google/高德瓦片加载或所有设备 GPU 合成时不发生黑屏。

上线前至少需要额外执行：①浏览器直接打开 `index.html`；②本地 HTTP 访问；③部署域名 HTTPS + 地图 API 域名白名单；④断网与弱网切换；⑤高德/Google 地形加载失败；⑥截图自动比较；⑦至少 iOS Safari 和 Android Chrome 的实际手势验证。

## 12. 后续优先级（必须与当前修复区分）

1. **P0｜真实照片离线交付。** 经合法许可后，先完成 FAST、花江大桥、科力寨、小花江村各 1—3 张经过来源校验的照片及地点级绑定；未核验的照片仍要标注范围，不得当作单栋建筑实拍。
2. **P0｜真实页面访问回归。** 在用户自己的浏览器通过 file:// 和 HTTP 分别重跑 `qa/real_browser_journey.py`；对源文件路径、跨域、图片、CSS、JS、控制台错误做截图和日志记录。
3. **P0｜线上 SDK 实效。** 有合法 API Key 后，检查真实 3D 地形的显示范围、坐标转换、地形加载状态与失败回退；保留离线模拟地图供无 Key 用户使用。
4. **P1｜桥梁实景级重建。** 不再用程序化立面冒充真实结构；引入可使用的公路路线、桥梁 CAD/官方剖面或开放地理数据，经坐标对齐再建桥塔、索网、桥面。
5. **P1｜图层碰撞与节点标签避让。** 对屏幕热点做碰撞检测，限制标签数量与图层顺序；实现移动端视口动态调整。
6. **P1｜FAST 游戏教学评估。** 以答题前后知识掌握为目标，增加每关“为什么”“实际应用”与可复盘错题；现有三个关卡属于可用原型，并不是完整教育游戏。
7. **P2｜键盘与屏幕阅读器无障碍。** 补焦点圈、Tab 限制、弹窗关闭后的正确回焦、语音描述和高对比主题。

## 13. 如何复核

在项目文件夹中运行：

```bash
python qa/static_regression.py
python qa/real_browser_journey.py
```

浏览器脚本默认使用**内联 HTML 模式**来适应当前受限运行环境。若要测试实际本地 Web 服务，先在 `Map demo` 目录运行 `python -m http.server 8080`，再在另一终端执行：

```bash
JOURNEY_URL=http://127.0.0.1:8080/index.html python qa/real_browser_journey.py
```

Windows PowerShell 将环境变量写成 `$env:JOURNEY_URL='http://127.0.0.1:8080/index.html'`，随后运行 Python 脚本。

结果位于：`qa/journey/journey-results.json`；截图位于：`qa/journey/*.png`；静态检查结果位于：`qa/static-regression-results.json`。测试失败不允许只依据旧的通过次数覆盖当前报告。
