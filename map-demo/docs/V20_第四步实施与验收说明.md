# 贵州3D交互地图 V20 第四步实施与验收说明

## 本阶段范围

基于V19多文件工程改造花江峡谷大桥和像素货车游戏。保留V17首次访问引导、V18任务状态机制、V19天眼三角色双时代任务，以及原始项目的HTML、CSS、JS、数据库、配置、脚本与资料目录。

## 主要问题及修复

| V19问题 | V20修复 |
|---|---|
| 大桥自动沿线播放后弹出三道单选题 | 在具体位置暂停，要求切换两个镜头观察后再作判断 |
| 仅凭文字即可完成桥梁观察 | 当前任务的视角操作是进入判断阶段的必要条件 |
| 进度条可跳过关卡 | 未完成的观察点成为播放和拖动进度条的上限 |
| 桥梁“变道”“鸣笛”容易暗示真实操纵 | 隐藏相应控件，A/D键调整观察方向；保留镜头和暂停播放 |
| 正确答题后没有成果对象 | 生成具体的观察记录、原因解释、后续线索并保存 |
| 货车只是逐站移动，然后答题 | 设置模拟任务委托，按当前位置核验站点，再进行交接判断 |
| 未来地点可提前点亮并被误计入当前任务 | 可以自由查看，但只记录“当前站点”的核查 |
| 三条章节貌似连续运输网络 | 继续保留各自独立的路段，不将虚线切换解释为实际交通 |
| ZIP前版中文工具文件名出现乱码 | 用原始Map demo ZIP还原20个文件名，恢复原始工具与目录 |

## 重点文件

- `index.html` 按玩法重写入口文案和新增样式/脚本引用
- `assets/js/ux/v20-journeys.js` 三次桥梁观察和三次道路教学配送任务；视角/节点核验、反馈、进度锁定和成果存档
- `assets/css/v20-journeys.css` 两种任务UI与移动端布局
- `assets/js/ux/game-hub-v16.js` 取消旧的重复问答浮层，保留统一游戏中心和档案导出
- `assets/js/drive/controller.js` A/D键改为观察方向，不再作模拟变道操作
- `assets/js/drive/drive-ui.js` 重命名“观景驻留”为“暂停画面”
- `config/project_manifest.json`, `config/build_manifest.json` 升级版本与事实边界说明

## 事实与情境边界

桥面至水面高差、主桥跨径与高速交通的相关内容遵照工程资料；货车运送展品、生活物资与农产品的委托均为**虚构教学情境**。项目中的桥梁模型、地形线形、公路线形及地点布局均非实测。FAST核心科研区不得因游戏示例而被解释为普通车辆可直接进入。实际道路规划、通行和高速停车规则应遵从真实的管理规定。

## 已完成的测试

使用离线内联的同一套HTML/CSS/JS在Chromium中执行如下测试：

1. 大桥新路线启动，进度条无法越过第一个未完成任务点。
2. 没有视角操作时，“完成观察”按钮保持禁用。
3. 完成两个观察视角与选择之后，显示独立解释结果，按用户确认后才继续。
4. 三个观察点均可走通，形成`bridge.observations`数组。
5. 货车不选道路或不领取委托无法出发。
6. 领取委托后必须核对当前位置档案才能前进。
7. 三站核对和G552终点判断形成完整记录。
8. 390和320宽度下无页面横向溢出。
9. 在上述浏览器检查中没有未捕获的页面脚本错误。
10. 打包时检查全部原始文件的路径均存在，并验证配置、CSS、JS、HTML与数据库路径。

本轮未测试全部真机、真实联网地图SDK、完整三条道路任务的人工实玩和大规模外部用户；这些仍属于第五步验收范围。

## 第五步建议

统一三游戏的视觉风格与文本密度，重点改善手机端游戏遮挡和分辨率下可见主体大小；邀请不了解贵州田野材料的初次用户独立完成三个完整任务，记录不理解、误触、放弃和错误推断点，并做可用性迭代。
