# V30 花江峡谷大桥驾驶位山体穿模修复

## 缺陷与根因

用户在驾驶位截图中看到一块绿色山坡穿过车道上方。模型中的桥面和引桥高度来自教学路线，而原有山体来自另一份未配准的概念高程。两套几何同时使用时，局部山坡高度高于驾驶路面，在相机视野里造成山体遮挡道路的现象。原始场景中存在例如 x≈-1080 的路面高度650、地形采样约799的交叉。

## 本轮修改

- 新增 `assets/js/geo/bridge-road-cut-v30.js`。根据已有驾驶路线的水平投影，沿道路中心和引桥创建显示用净空带，调整高于路面阈值的显示地形顶点。
- 保持道路中心线、建筑、原始高程数组和数据库内容不变。通道两侧用平滑过渡控制地形降低量，离开通道后返回原始地形。
- `assets/js/scene/engine.js` 的 Canvas 地形绘制与 `assets/js/scene/webgl-terrain-v25.js` 的 WebGL 顶点采样共用同一个地形净空函数，避免两个渲染模式出现不同的相交关系。
- 对整个教学路线包含驾驶位、乘客位、电影视角的运行路径进行复测。

## 验证结果

- `node qa/V30_桥梁净空回归测试.cjs` 的603个道路中心/两侧采样检查通过，路径采样中道路与修改后的显示地形没有交叉。
- Chromium 对1280×800桌面和390×844手机驾驶位、乘客位、电影视角进行截图测试，没有未捕获的脚本异常和横向页面溢出。
- 原始 `assets/data/database.bundle.js`、地形数据、配置与数据库均未修改；修复针对显示层。

## 事实边界和遗留问题

此净空带是对概念场景几何冲突的修正，不代表真实道路开挖、坡道断面或测绘高程。由于未导入实测DEM以及桥梁BIM资料，暂不能声称达到实景级地形。WebGL2路径已共享净空算法，但受测试环境GPU上下文可用性限制，仍需在真实WebGL2设备上做深度、遮挡和性能验收。施工工程场景若使用实测DEM应通过实测道路高程及工程构件重建替代本净空示意。
