# 贵州3D交互地图 V34 地形恢复与驾驶视角回归修复

## 一、修复结论

V33驾驶位出现大面积空白地形的直接故障，来自 `assets/js/math.js` 的颜色解析函数 `M.hex()`。它仅解析 `#RRGGBB`，但 `M.mix()` 的返回值为 `rgb(r,g,b)`。`renderTerrain()` 连续多次混色，后续调用把 `rgb(...)` 误解析为十六进制，使结果产生 `NaN`，浏览器无法为无效 `fillStyle` 正常绘制山体。

本轮将 `M.hex()` 修为同时识别十六进制和 `rgb()/rgba()`，新增嵌套混色回归测试。恢复山体后又处理了镜头近裁剪和过宽的道路地形净空。

## 二、修改说明

1. `assets/js/math.js` 颜色解析支持 `#RGB`、`#RRGGBB`、`rgb()` 与 `rgba()`，修复连续混色导致的无效填充色。
2. `assets/js/scene/engine.js` 增加摄影机近裁剪面的地形多边形裁剪，仅丢弃完全不可见的面片；驾驶时采用视窗范围过滤，避免近景整块山坡突然消失。
3. `assets/js/geo/bridge-road-cut-v30.js` 将显示用道路净空的侧向削切半径从360缩小到155场景单位，并将道路核心净空半宽从60缩小到29，避免大范围削平峡谷。此为程序化演示几何，**并非测绘、施工土方或实测山体**。
4. 地形网格的兼容模式绘制预算从2800提高到5200个目标网格单元，改善原有高程采样的坡面层次，但不虚构新的实测高程。
5. 新增 `qa/v34_terrain_color_regression.cjs` 验证多次RGB混色不会生成 NaN；截图保存在 `qa/v34/`。

## 三、已测试内容

- Node JavaScript语法检查与连续混色单元测试通过。
- 离线Chromium 1280×800及390×844视口渲染截图通过人工检查，主地图、驾驶位约5%、20%、52%路段及电影视角均渲染出山体，未见之前的大面积地形缺失。
- 复用 `qa/v33_browser_regression.py`，桥梁五关、双工程调查三章、天眼三角色入口在桌面与手机端通过；测试路径无未捕获脚本异常，无横向溢出。
- 浏览器使用Canvas兼容路径。WebGL2真实GPU驱动、长时间帧率和复杂天气场景尚未实测。

## 四、数据和文件保留

V33原有文件路径全部保留。原始高程采样、地理锚点、数据库、配置文件和现有游戏任务未被覆盖。仅修改三个原有JavaScript文件，并新增测试、截图和说明文档。

## 五、仍未解决的结构性问题

- 仍采用历史版本的概念地形采样，无法直接还原真实岩壁纹理、植被与地层。
- Canvas绘制的面片排序仍属于近似方式，不能完全替代真实GPU深度测试。
- 程序化道路净空仍缺少测绘与土木设计资料支撑，只能作为教学场景防穿模方案。
- WebGL2真实GPU验收、车辆精细三维资产和高分辨率PBR材质仍需另行完成。

## 六、下次迭代不得破坏的回归约束

1. 路面在第一人称驾驶位必须连续可见。
2. 画面内道路两侧山脊在同一摄像机视角必须存在，且不允许出现 `rgb(NaN)`。
3. 山地不得穿透路面、护栏及车内视线。
4. 地形的削切仅用于可视化道路净空，不得修改原始DEM或者把概念地形认作真实测绘成果。
5. 即使启用未来GPU渲染，也必须进行道路、地形及水面统一深度和真实设备截图验收。
