# V16 交互游戏深度优化与技术说明

## 一、改造边界和实际实现

本轮是基于既有 Map demo 项目的源码增量改造，保留原始空间引擎、SQLite 数据副本、三片区切换、时间轴、节点面板、桥梁四视角驾驶和像素货车的章节地图。游戏改动以脚本及CSS层承载，无须新增服务端。游戏剧情只影响本地学习记录，不会篡改地图数据库中的历史节点。

关键新增文件如下。

| 文件 | 功能 |
| --- | --- |
| `assets/js/fast/role-adventure.js` | 三角色、双时代、18任务的状态与反馈、互动模型、记录保存及地图考察返回 |
| `assets/js/ux/game-hub-v16.js` | 统一入口、学习档案、三款游戏状态汇总、桥梁3个观察点、货车3章判断任务 |
| `assets/css/v16-games.css` | 桌面与移动端游戏界面和交互控件样式 |
| `index.html` | 启用上述文件，升级游戏入口说明，保留原地图资源 |

## 二、中国天眼任务内容

| 身份 | 建设时期（2011—2016） | 运行时期（2020年起，地图2022节点） |
| --- | --- | --- |
| 科研人员 | 洼地证据、主动面与馈源协同、测量偏差复核 | 模拟观测协同、信号特征比较、候选复测流程 |
| 建设与运维人员 | 认识结构、局部构件装配测量、警报处置 | 设备数据巡检、维护协调、工程知识解释 |
| 普通公众 | 生活空间标注、社区问题交流、未解事项归档 | 分区参观判断、电磁环境科普、兼顾地方生活的导览 |

每段包含3个任务，全部18项已实现并经自动化通关测试。任务具有资料查看、模拟设备操作、带理由的判断及回顾记录等互动。错误判断不会直接导致游戏历史失败，而是提示玩家回到证据继续核对。各任务只有经过预设的最低调查量或完成教学装置校验才能归档。建设期角色的记录会在运行期出现提醒，尤其普通公众角色的未核实问题不会被自动写成已经解决。

这里实现的是**教育游戏的状态机和可玩的模型级交互**，并未实现真实CAD构件拖拽、实景射频测量、可视化三维地理GIS精度或者真实采访者的NPC交谈。Canvas主体为可旋转的概念透视模型；3D原地图通过「回到3D主地图考察」入口供任务中查看，任务状态可以恢复。后续若需要更深层的空间联动，可把任务的证据点转换为真实地图节点的可点击图层。

## 三、桥梁和货车的教育改造

花江驾驶仍采用原有模拟路线与七幕章节，新增三个自动暂停观察点。题目分别讨论625米桥面至水面的高差、1420米主桥跨径，以及高速交通与村内道路的不同尺度。学习者需要选择有根据的解释才能继续行驶。三项记录保存在统一档案中。

像素货车仍保留三条独立章节，新增终点交通证据任务。G552强调接入方向与实测导航不能混同，S315强调道路分级，六安高速章节强调干线交通与周边村镇道路的差别。不同章节不会绘制虚构的跨区连续道路。

## 四、交互与状态设计

所有FAST任务共享同一数据结构：身份role、时代era、当前任务index、查看证据visited、设备滑块sliders及本地归档records。进度通过浏览器localStorage键 `guizhou-games-v16` 保存。桥梁与货车分别记录观察点和完成章节。游戏中心提供JSON导出与确认清除。不上传个人数据。

主页面已连接角色与时代选择、地图节点时间切换、镜头观察、参照资料、差异化任务、反馈、进度归档，以及移动端响应式布局。地图引擎的主相机由原App管理，FAST教育模型单独绘制，不修改工程实体。FAST体验退出时返回原地图；地图考察模式可保留任务继续体验。

## 五、科学与史料依据

FAST于2011年3月开工、2016年9月25日落成、2020年1月11日通过国家验收正式开放运行。科学操作概念采用固定球面反射面、局部主动调形、馈源索驱动精密定位和射电信号核验的基本框架。分区设定的5公里核心区、5—10公里中间区和10—30公里边远区依据2019年保护办法，禁止把该条文作为2011年已生效的法规使用。

公众与社区剧情来源于大型工程与地方社会互动的一般性研究议题，与项目原有田野调研的关注方向保持一致，但所有合成对话、居民人物、家户空间、设备故障、观测曲线均清晰标记为教学材料，未冒称真实采访、历史事件或科研成果。

## 七、下一阶段优先级

如果要将作品提升为具有真实场景交互能力的研学产品，建议优先落实工程与调研素材权属，整理真实受访者授权与原话核验表；再将任务证据点与地图数据库中真实节点关联，制作三维构件动画与分层结构模型，补齐多种设备操作结果和完整的教学评测。对未核实的历史场景继续保持示意标注。
