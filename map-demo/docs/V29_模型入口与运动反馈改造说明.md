# 贵州3D交互地图 V29 · 现场入口、驾驶连续路面与游船运动

## 修改目标
针对原图中驾驶座前方路面断裂、双区域地形缺乏工程识别度、游戏入口远离建筑、游船运动不明显的四项问题，进行局部、可回退的改造。

## 实施

- `assets/js/scene/engine.js`：驾驶道路四边形在相机近截面进行三维多边形裁剪并按远近绘制，不再丢弃靠近镜头的道路段。道路中央虚线使用路径法向展开，避免巨型屏幕空间三角形。双区域总览提升高差比例和坡面明暗，并加入桥塔、桥面、FAST反射面轮廓。
- `assets/js/ux/v29-world-portals.js` 与 `assets/css/v29-portal-depth.css`：在主工程模型的投影坐标上绑定快捷入口。花江大桥入口打开过桥准备，天眼入口打开像素NPC冒险。总览中两处工程也能直接进入相应游戏。此处是投影标记，不等于精确三维碰撞体。
- `assets/js/drive/river-cruise-v26.js`：保留推力与阻力形式的教学速度估计，航行位置使用18倍演示时间推进，标注“加速演示×18”。区别船速数值与动画时间倍率。
- `assets/js/scene/engine.js`：增加有限数量的“岸线观察点”参考标志，让跟船视角可观察相对位置变化。这些标志并非真实码头或地标。
- `assets/js/app.js`：双区域镜头对准两个工程地形展示中心。
- `index.html`：加载新增JS、CSS，添加现场入口按钮。

## 限制与下轮工程条件

- 本次没有新的真实DEM、河道测绘、车辆BIM或FAST工程CAD。继续使用原始模拟高程及概念模型。
- 双区域仍是基于已有高度采样的3D投影示意，不具有可核验的地理精度。
- 物理反馈遵循一组简化运动方程，尚未经过独立水动力学或车辆动力学验证。
- 无Blender场景源文件、专业GLB资产或GPU硬件级验收，不可将此版本描述为影视级实景重建。
- 为达到高真实感，需要优先补足经过地理配准的DEM、河道中心线与岸线、桥梁BIM/摄影测量等来源，并在GPU环境验收真实深度遮挡、PBR、阴影和载具碰撞。

## 保留原则
以V28全量工程为基线。原文件没有删除，地形采样、数据库与旧配置保留不覆盖。原有导航和三款游戏继续存在。
