本轮从 V20 多文件工程继续开发，保留其 `index.html`、`assets/`、`config/`、`database/`、`backend/`、`docs/`、`qa/`、`tools/` 和启动脚本。没有将项目替换为单文件页面。

- `assets/js/scene/engine.js` 在原有 Canvas 2D 投影中为地形面片增加按坡向计算的定向漫反射和随距离变化的雾化；FAST 使用更细分的明暗面片和反射线展示。新增精细与平衡两种地形绘制档位。精细档通过增加网格密度与像素倍率提高近景可读性，不能理解为真实 PBR 材质系统。

- `assets/js/db.js`、`assets/js/state.js`、`assets/css/tokens.css`、`index.html` 新增更接近自然地貌的日光主题，保留原有三套主题。

## 真实建模与工程仿真的距离

目前的主地图渲染器采用 Canvas 2D 投影，地形样本并未证明来自高精度地形测绘。设备面片是程序构造的教学几何体，场景仍缺少实拍三维重建、标准 GLB/GLTF 模型、真实法线贴图、PBR 金属与粗糙度、实时阴影、GPU 深度缓冲以及专业刚体/柔体求解器。现阶段不能将其表述为“真实 3D 数字孪生”或“工程级物理仿真”。

建议后续建立 GPU 渲染层，采用 WebGL2 或 WebGPU，并保留现有 Canvas 2D 作为低配后备。优先制作来源明确的 FAST 主动反射面、馈源舱、支撑塔、索网与花江大桥桥面、主塔、主缆和吊索模型。针对重要近景构件使用高低模、LOD 与可验证的 GLTF 资产清单。地理底座须引入具有授权的 DEM/DSM、正射影像及测绘控制点，并将模拟地形与真实地形在 UI 中明确区分。

科学与工程数值采用分级方法。当前教学模型只表达方向和依赖关系；进入科学解释级需要真实天线几何、误差分布与相关论文；进入安全与结构工程级则需要有资质的专业团队确认载荷、边界条件、材料参数以及校准与误差报告。工程安全模拟须经专家审核后才能对外声称具有预测能力。

## 还需执行的真实性验收

1. 资产清单逐一标注来源、作者、许可、标定日期、坐标与尺度基准；缺少这些条件时不得标注“精确还原”。
2. 对 2011、2016、2020 等场景提供对应的历史资料依据，避免用建成模型代替建设期。
3. 在真实 Windows、macOS、Android、iOS 设备上验证各档帧率、峰值内存、加载时长和失帧情况。
4. 邀请不熟悉工程与论文的用户独立尝试，观察能否读懂任务目标，是否知道如何通过滑块改变结果。
5. 验证学习内容准确性，特别是 FAST 球面与工作时局部近似抛物面的区别，以及桥梁风振模型的局限。
