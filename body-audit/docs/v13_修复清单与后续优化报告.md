# 《肉身审计局》v13｜玩家体验问题的针对性修复、验收与后续方向

> 来源：v12 原工程及《v12玩家视角全流程问题诊断与优化路线图》。本轮修改的是**游戏源码本身**，保留三幕和3D架构。本文件区分已完成、部分完成、未完成，避免将技术测试替代真人玩家体验结论。

## 一、这次优先修的不是视觉，而是信任

从普通玩家视角，如果“我说的”和“AI回的”不一致，“我选的”和“报告写的”相矛盾，再好的3D材质也无法让人看懂故事。v13 因此采用一条主线：

**第一幕：我的症状与资料，如何影响本平台的复核申请？** → **第二幕：我真实说出的哪句话，被记录时省略了？** → **第三幕：一次实际身体动作，如何变成有来源、合同、调用与收入的样本？**

这三个情境之间不是虚构同一家公司或同一套AI，而是围绕“身体被记录、解释和使用”形成一次逐步发现。

## 三、用角色行为验证叙事是否可信

### 1. 第一幕｜当前实际结果与假设对照不再混淆

- **林舟，允许旧记录**：实际可提出本平台的人工复核申请；这不表示已完成真实医院预约。
- **林舟，拒绝旧记录**：实际需补资料；对应的对照也保留“本次拒绝授权”这一事实，**不再在同一页宣告林舟可以申请**。
- **周远，允许授权但无法检索旧记录**：显示需补资料，不推断病更重。
- **明确警讯**：优先提示寻求医疗帮助；不等待病历评分。**不确定**：保持待核实，不直接宣称受阻。

### 2. 第二幕｜原话真的来自玩家

旧版本中，赵伯提出“去县城得安排车”，AI却立刻说他讲了另一条症状。新版本先回应交通顾虑，然后让玩家自己选一句真实症状表述。如果玩家说：“一走快就气短，坐下来好一点。”，机器初稿只记“坐下来好一点。”，玩家能在下一步准确补回“气短”。报告引文直接来自该次选择。

### 3. 第三幕｜不是开始就让工人已经下岗

伊森可以先看两份既有样本，但会看到“历史采集”的明确标注。切换阿玛拉后，系统进入**本局新采集合同选择**，不抹掉历史流水、不把历史工资当新赚的钱；旧许可不被新合同覆盖。玩家仍能继续实际动作采集。

## 四、测试证据与边界

- `npm test`：**21 / 21** 通过，涵盖会计守恒、限次许可、WebGL几何的静态/碰撞条件、反事实不覆盖真实结果、危险词否定/未知/转折解析、老人原话漏记对应关系、历史与新许可隔离。
- Chromium页面操作：林舟拒绝授权的真实/模拟结果一致；点击“回看对话”恢复聊天；点击X/Esc不会陷入空场景；返回街道后的聊天草稿仍在；紧急警讯优先跳过旧病历授权；赵伯交通问法和实际漏记句子正确关联；平台→劳动者可重新签新合同。页面脚本错误监听在已测路径未报错。
- **浏览器测试方法**：将离线单文件注入 Chromium 页面；部分专项路径关闭3D渲染循环，使叙事与交互测试不受低性能软件3D影响。这不是完整GPU实时画面/性能验收。
- **尚未进行**：真实未接触过论文的玩家盲测、跨浏览器GPU性能、所有角色×所有对话×全部分支的穷尽测试。

## 五、下一轮最有价值的任务

1. **真实行动后果**：周远整理症状卡与寻找线下帮助形成一个可操作微任务；林舟能比较旧体检与新症状，而不只看两张状态卡。
2. **证据驱动结局**：让玩家主动把问诊回执、自己的原话、D-编号样本放到一个证据面板中，选择哪条规则产生差异；解释只在作答后显现。
3. **更自然的输入系统**：开放输入必须有可核验的意图映射和“不理解时请求澄清”，不能默认为任意医学智能助手。
4. **工厂动作深度**：制作真正的准备姿势—身体动作—采集确认—平台复用的一体化场景，明确谁在时间和劳动上付费。
5. **6–8名零知识真人盲测**：验证玩家能否复述第一幕结果、分清事实和模拟、说明三幕共同主线；不要在测试前声明理解率达标。

**制作判断**：v13 的价值是让玩家开始相信“我说过的话真的进入了游戏，我的选择真的被记住”，而不是声称已经完成全部商业级叙事升级。
