# 《肉身审计局》v11：真实感视觉升级与影视级资产生产规范

> **交付性质：可玩的实时视觉精修原型，而非照片级写实/3A成品。** 该界限十分重要：目前尚无高精度扫描人物、专业 PBR 材质贴图、骨骼蒙皮、动作捕捉与专业光照烘焙；不能把程序化灯光冒充完整物理渲染，也不能把软件三维投影截图冒充实际 GPU 测试。

## 一、为什么 v10 看起来不够真实

1. **表面是纯颜色**。即便有透视，建筑、皮肤、玻璃、钢材之间没有足够的粗糙度、反射和微表面变化。
2. **光线缺乏叙事来源**。夜景有明亮窗格，但人物与物件缺少对应的局部照明，空间显得像模型展台。
3. **低模人物没有细致的面部结构**，服装、鞋底与环境的接触不足，像塑料玩具。
4. **建筑的建造逻辑不完整**。没有足够的门窗五金、幕墙框架、雨棚厚度、台阶、排水件与地面尺度参照。
5. **界面与游戏世界断裂**。问诊 UI 使用了戏剧化面板语言；而真正的问诊应是令人可信的、可阅读的医疗产品界面。
6. **电影化不能只是暗角和颗粒**。镜头、主角占画面比例、轮廓清晰度、阴影和移动可控性，优先级高于炫技滤镜。

## 二、v11 已落实到真实代码的修改

### 实时 3D
- 重写 `js/world3d.js` 的 WebGL1 着色器：半球环境填充、方向性主光、两组局部灯、距离衰减、非金属/金属近似高光、世界空间多尺度噪声、雾化及压缩高光。**属于近似材质模拟，不是工业标准金属度/粗糙度 PBR。**
- 软件回退也同步调整照明与雾的计算，使 WebGL 不可用时至少能够观察光照层次，但它使用 Canvas2D 深度排序，细小几何相交处可能发生遮挡瑕疵。
- 城市：增加门窗框、街店入口、雨棚、门槛、地砖缝、排水格栅、街边标识、花坛和路边光区。
- 乡村社区：增加诊室入口及坡道、窗框、候诊长椅、地面磨损标记等具备功能的道具。
- 数据工厂：增加钢结构、设备指示灯、控制台细节、动作追踪参照、工位警示线、工具台屏幕与货箱结构。
- 人物：增加五官、眉眼、鞋底、衣领、腰带及服装局部件，并纠正伊森位于高处控制平台时的脚部落点。

### 产品 UI/UX
- 新增 `css/cinematic-v11.css`：将问诊界面调整为更清晰的医疗产品视觉语言，减少纯装饰性发光，改善消息气泡、可点击选项、输入区、卡片和真实移动端触控尺寸。
- 提高原来过小的提示字号；控制说明优先呈现在玩家确实需要的时候；关键信息与剧情结果的阅读优先于空间特效。
- 保持 v10 **角色与事件因果对应** 的导演规则：并非选了中产或北方视角就自动出现血红色受压迫过场。

## 三、真实验收范围

- 本轮 `npm test`：**17/17 通过**，覆盖三维场景、几何有限性、主要碰撞、问诊权限与紧急症状、数据交易与分账逻辑。
- 使用 Chromium 实际渲染 **1440×900** 周远路线、**390×844** 林舟路线，两条路线从开场、选角、进入问诊室到弹出结果报告均成功，测试中无未处理 JavaScript 错误。
- 工厂的两个视角完成单独的 **3D 场景截图/渲染烟雾测试**，没有把这项测试夸大为完整工厂通关或人物骨骼动画验收。
- 本测试环境无法启用 WebGL GPU，`document.body.dataset.renderMode=cpu-3d`；截图全部注明该模式。**真实 GPU shader、光照和最终像素表现仍待设备实测**。
- CPU 投影后端仍能看出多边形边缘、建筑面片交错和低模角色；离用户提出的“照片级写实”差距显著，不作虚假达标陈述。

## 四、下一阶段实现照片级写实的生产要求（必须补齐）

| 资产/模块 | 需要的来源与质量 | 具体验收办法 |
|---|---|---|
| 主角人物 | 原创或合规授权高精度人物扫描／雕刻，约 3–5 万面游戏 LOD0，面部精细拓扑，独立服装与皮肤材质 | 近景 1.5 米内，检查脸部结构、眨眼、皮肤法线、装束与体型，不能只靠国籍或肤色区分身份 |
| 骨骼动画 | 角色 rig＋走跑停转、抬手触屏、坐起、弯腰、抓取与疲劳微动作；动作捕捉或人工精修 | 至少 8 个状态，起步/刹停脚底不穿模，触屏有真实触点；测试不同帧率 |
| 城市与诊室 | 真实尺度建筑道具、门窗洞口、地面 PBR 与磨损、街道设施，合规获取纹理与模型 | 地表 1:1 尺度，墙面实体厚度，门可通行，遮挡不影响交互热点 |
| 工厂 | 传送带、采集框、摄像头、安全装置、码放箱、控制台与阶梯，所有设备有真实尺寸 | 角色与道具无穿插；关键人机空间有可见用途，不是背景形状 |
| 材质 | 2K/4K PBR BaseColor、Normal、Roughness、Metallic、AO，正确 sRGB/线性空间 | 光源移动时反射变化一致；皮肤、塑料、金属与湿地材质能区分 |
| 渲染 | 采用成熟引擎/运行时（如 Three.js + Blender/glTF，或 Unity/Unreal）接入阴影贴图、IBL、色调映射、环境雾、可控的后期 | 在真实 GPU 浏览器或目标设备进行逐帧截图比对、内存与帧时间监控 |
| UI | 现实医疗聊天产品/工业采集管理台两套组件库，以人类视角为核心 | 交互主要目标明显；390px 宽屏正文 ≥ 12px，主要按钮 ≥ 44px，高对比无误触 |
| 音频 | 城市交通、诊室空调和脚步、工厂机器低频、明确的交互反馈，使用原创或授权素材 | 剧情冲突时声音变化有因果；默认可静音，降低动态效果有效 |

以上数值是制作目标，不是当前测得数据，也不保证任意设备达到商业 3A 标准。应先锁定一间**城市问诊入口**和一名**周远角色**，制作“走近—停步—抬手—触屏—进入聊天”的完整高精度垂直切片，再推广到另外两个关卡。

## 五、空间制作审核门禁

依照 `build-3d-game-rooms` 的阶段管理：

- **Function：待审。** 需要确定最终相机、角色占屏比例、通行净宽、主道具与镜头目标，审定黑白平面及道具参照图。
- **Asset：未开启付费提交。** 没有生成/上传高精度付费 3D 模型，也没有使用 Meshy API 积分；用户需先批准具体道具与参考图，并明确同意任何可能收费的服务。
- **Form：未通过。** 未有 Blender 封闭实体外壳、实际 Boolean 门窗、挂装/贴墙校准、世界空间碰撞和正式多角度评审。
- **Runtime：未通过。** 尚无实际 GPU 环境与最终角色资产的加载/性能验收。

因此本次可试玩包定位为“高保真方向的游戏迭代原型”，而不是“最终 3D 房间批准与发布”。

## 六、下一次迭代的具体验收工单

1. **P0 真实人物垂直切片**：替换城市主角的低多边形身体，给出 glTF/GLB 及动画 clip，并从玩家生产相机复核近景；没通过前不扩张场景数量。
2. **P0 真正的 PBR 材质**：替换着色近似，接入法线和粗糙度贴图，区分皮肤、塑料、钢、玻璃，固定色彩管理。
3. **P0 可交互的动作链**：通过连续动作展示踏步、停顿、触屏，避免触发动画代替真实行为。
4. **P0 GPU/CPU 分层**：低配设备自动退回简化模型与更少灯光；并验证没有操作延迟或文本遮挡。
5. **P1 电影摄影**：根据角色身份镜头、景深与叙事重点重新标注；压迫仅由实际事件触发。
6. **P1 无引导盲测**：至少 8 位从未见过剧情的玩家，逐幕记录“我是谁／做什么／发生什么／下一步”的回答。

**关键判断**：照片级真实感不能仅靠升级 CSS 或添加几个 3D 盒子完成。游戏世界中人物、道具与动作的空间一致性，必须先于更猛烈的滤镜。
