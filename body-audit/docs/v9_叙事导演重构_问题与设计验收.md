# 《肉身审计局》v9：血色裂隙——三幕叙事导演重构、舞台调度与体验验收

> 交付性质：**已实现的 v9 可运行重构版 + 尚待开发的导演与美术生产方案**。版本依据是 v8 工程源文件（`js/game.js`、`js/data.js`、`js/engine.js`、`js/world3d.js`）；改动集中在叙事、主动解释机制、情绪节奏和结果承受机制，不冒充已完成高精度 3D 骨骼物理或正式玩家研究。
>
> 一句话要让玩家带走的判断：**身体进入系统后，数据不只是描述身体；它会成为服务的门槛、经验的过滤器和价值的分配依据。关键是谁制定了这种转换的规则。**

## 0. 原先为什么“都玩了，却不知道游戏想讲什么”

这个问题不是文案没写够，而是叙事失去主谓宾：玩家不知道“我在经历什么”“伤害发生在什么地方”“我的回应对现实有什么改变”。实际 v8 机制里，第一幕已经会弹出双角色对照，但往往同时塞进完整度数字、解释、反事实按钮、切换角色；第二幕呈现转写差异，但缺少视觉上的消失时刻；第三幕有可核对账本，却未把劳动时间和复用收入塑造成同一个情绪冲突。

现有六大深层问题：

1. **主题解释晚于体验结束。** 关键概念只在报告或结局出现，玩家在故事中无法“看见”判断规则的力量。
2. **行动和现实代价脱节。** 日结工补档案会损失时间和收入，但旧版只描述门槛，不必承担其后续选择；被漏记的症状只是文字不同；平台再用一份数据与采集者身体时间之间的分裂不明显。
3. **三个案例的“连接”是旁白，而不是线索。** 章节切换像换题目，上一章的发现没有在下一章再次变形出现。
4. **画面缺乏情绪梯度。** 均衡蓝金夜景能够稳定，但无法区分“普通生活”“异常出现”“规则暴露”“身体反抗”“证据收束”。压迫不能全部靠负面文字讲解。
5. **身份视角容易再次滑回上帝视角。** 前文已修正了普通人突然改规则的问题，v9 必须继续把角色实际能采取的行为和复盘阶段的模拟严格分开。
6. **理论概念与虚构情境的证据边界不够显眼。** 资料完整度并非医学风险；城市/乡村、全球南/北身份不直接代表健康程度或个体价值；课堂假想评分不能当作真实医院诊断或真实工资统计。

**重构原则：一幕只让人发现一种转换、一种代价、一条证据。** 三幕结束，证据会组成同一条生产线。

## 1. 新导演命题与叙事对象

### 1.1 概念与戏剧问题

- 表层任务：一个人想问问身体；另一个人想解释自己的症状；第三个人想拿到一天工资。
- 中层冲突：一个系统要求身体先被转成“可检索、可标准化、可复用”的形式，才能被其正常处理。
- 深层主旨：**数据如何成为规定身体可见性、解释资格和经济价值的媒介？**
- 反向力量：人试图将自己的经历重新带回制度——留存原话、寻求人工帮助、追问许可与收入。强调人的主动性而不是技术决定论。

本游戏的主角不是“万能的审计员”，而是若干现实位置不同的人。所谓“审计局”，是玩家在跨越三段经历后获得的一种观察能力，而非进入游戏时就拥有的行政权限。

### 1.2 三枚贯穿的证据

| 章节 | 具体证据物 | 技术转换 | 现实回响 | 核心字幕 |
|---|---|---|---|---|
| I | 一条旧病历检索状态 | 记录完整度 → 服务入口 | 补档案需要时间、请假、额外成本 | **被挡在门外** |
| II | 一句未被保留的症状原话 | 身体感受 → 结构化转写 | 被漏记的胸部不适可能难以传达给下一位医生 | **这句话，没了** |
| III | 带唯一编号的动作样本 | 身体劳动 → 可复制资产 | 采集有工时和疲劳，调用却可反复产生收益 | **她只做了一遍** |

最终主题只通过这些**玩家已经看见的物件**来提出，不再额外塞入未经体验的理论课。

## 2. 全局导演节奏：五拍一幕

一幕的标准结构不再是“点按钮 → 报告 → 下一幕”，而是：

**生活需要 → 正常交互 → 矛盾暴露 → 电影化裂隙 → 身份内行动与证据归档**。

- **生活需要：** 说一句日常话。人物不复述理论术语。镜头中允许环境继续呼吸。
- **正常交互：** 交互目标明确；屏幕正常工作，故事没有预先宣布“AI必然歧视”。
- **矛盾暴露：** 在可核对的细节处出现异常：服务门槛、转写遗漏、二次调用收益。
- **电影化裂隙：** 蓝灰世界失色，红色像血管/裂痕一样进入画面；关键命题以 4–10 字的大字幕独占镜头。短暂展示后才出现白底证据卡。
- **身份内行动与证据归档：** 玩家只能做该人物能做的事。之后看见后果，并收获一件证据。

**重要的镜头规则：先冲击，再解释。不要让血色大字压在可阅读的白底卡片上。** v9 中第一幕、第二幕和首次工厂调用已采用独立冲突节奏；减少动效可缩短过场。

## 3. 三幕详细分镜与台词

### 第一幕：资料齐全的人不一定病更重

**场景：** 城市夜街，同一台“陈俊良问诊室”。日结工周远刚搬完货，白领林舟结束加班。两个人都只是想问问身体；不能直接修改院内规则。

**玩家行动：** 选择角色、走近问诊机、说出不舒服、回答症状的时间与警讯、决定是否允许调取既往资料。

**异常揭示：** 在固定相同症状、相同资料授权意愿的模拟对照里，旧记录是否可检索导致非急诊人工复核入口不同。页面明确区别真实玩过的角色回答与另一角色的情境推演；急症警讯不得被档案缺失降级。

**导演瞬间：** 世界调暗，出现暗红色的细长裂缝，主字幕“被挡在门外”，副字幕“症状没有改变，档案却决定了等待的顺序”。此时暂时不出现报告 UI，让玩家先经历隔绝感。

**恢复普通世界之后，打开一张证据卡：** 说明“资料完整度不是疾病风险分数”。两人身份不是医学病因，问题是系统将资料覆盖作为服务资格的代理指标。

**现实内行动：** 新增“请假补资料”与“先保存症状、联系人工求助”两种应对。对周远，补档案意味着可能损失找活时间和一部分收入；对林舟则意味着挪出会议/项目安排。后者仍然面临新症状可能被旧记录遮蔽的问题。这里没有“给系统按下公平开关”这种超权限幻想。

**章节落款：** “我说身体不舒服，机器先问我有没有档案。”

### 第二幕：被听见，不等于被记录

**场景：** 乡村/城镇诊室。选择赵伯或许阿姨。两人的语言、既往就诊情况和线下可及性不同；不预设某种口音必然识别错误。

**玩家行动：** 说出原话 → 看到机器初步记录 → 选择是否纠正 → 提供或不提供既往记录 → 选择线下联系路径。

**异常揭示：** 赵伯所说“胸口有时发闷”在虚构转写中被漏掉；许阿姨说“和以前不一样”的新症状可能被旧病历模板盖住。错误来自特定的技术处理，而不是长者“表达能力差”。

**导演瞬间：** 巨大字幕“这句话，没了”。证据报告并排显示原话、机器的错误摘要、玩家确认后的内容；使用血红删除线和青绿色补回的文本。不要把真实病痛画成医学上的血腥镜头，以避免让玩家误以为诊断已确定。

**现实内后果：** 补回一句话改变的是**传给下一位接诊者的材料**，并不能自动完成预约和转诊。交通、家人陪同、医生可及性仍然是无法由一键“数据纠正”抹去的条件。

**章节落款：** “我明明说了，但它没把那句话留下来。”

### 第三幕：身体劳动的时间不能被无限复制

**场景：** 阿玛拉在低处的动作采集工位；伊森在高处的控制平台。这个高低差表现数据权限的差异，而非断言地理或族裔天然高下。

**玩家行动：** 阿玛拉选择劳动合同，准备、录制、核对、上传，完成一定数量后可以休息；伊森先检查来源和许可，再调用已上传的数据。

**异常揭示：** 每次采集都需要身体时间并产生疲劳，一份样本上传后可在有效许可范围内被多次调用，调用账目会产生新收益。买断、分账和限次合同有不同后果。

**导演瞬间：** “她只做了一遍”。3D 场景暗下来，红色轨迹从工位沿数据通道流向控制台；控制台亮起而工位维持在阴影中。完成十份订单后出现另一句“工位熄灯了——已经上传的数据不会一起消失”。这表达岗位关系与数据复用，不呈现不可证实的种族差异数字。

**行动后果：** 玩家打开同一份交易凭证，看到样本编号、原采集动作、单次工资、调用收入及分账。数值均为虚构教学模型，收支由可复核的交易引擎计算。

**章节落款：** “她做过一次的动作，可以在另一个屏幕上变成很多次收入。”

## 4. 视觉语言：血红不是纯装饰

| 游戏状态 | 色彩 | 音响与画面 | 玩家应感受到 |
|---|---|---|---|
| 普通生活 | 深海军蓝、温暖灯光 | 城市/诊室常态、人物小动作 | 事情看起来没问题 |
| 异常刚出现 | 降低饱和度、偏灰 | 环境呼吸变弱、声音减少 | 我的某种经验没有被认可 |
| 信息被剥夺 | 暗红、血色细线、裂隙 | 短暂大字、光线脉冲、低频停顿 | 一条规则跨过屏幕触到了生活 |
| 玩家补救 | 暖白纸张、青绿“恢复” | 记录可以被纠正，但不能神奇地改变世界 | 人有主动性但受现实限制 |
| 最终证据 | 炭黑、骨白、鲜红强调 | 三枚证据合并 | 原来三幕是一条链 |

本次 v9 已新增 `css/director-v9.css`、`js/director-v9.js`、穿透画面的赤色线条、暗角、冲突字幕、证据条、报告红色主张区、第二幕删除/恢复排印、第三幕调用瞬间反馈，以及新结局陈述。

**关键约束：** 红色表达“结构性暴力”的**隐喻**，不把算法偏差虚构成某种真实人体流血结果；不以大量真实伤口和恐怖镜头压倒人物处境。支持系统级 `prefers-reduced-motion` 和游戏内“减弱动效”。不让动画常驻到妨碍阅读的区域。

## 5. 交互与镜头实施原则

### 5.1 玩家绝不越权

日结工可以说症状、保存记录、就诊求助、请假；不能调整医院分流算法。老人可以核对自己的原话、联系家人与附近医生；不能远程改写医院模型。采集工可以在合同中做选择、劳作与休息；不能凭空改变平台后端收益政策。平台人员可以调用样本但需要遵守许可限制，任何违规场景必须写出真正规则后果。

### 5.2 状态机

- `city_chat` → `city_rupture` → `city_report` → `city_cost` → `bridge_2`
- `rural_chat` → `rural_rupture` → `rural_report` → `bridge_3`
- `factory_capture` → `factory_inspect` → `factory_invoke` → `factory_rupture` → `factory_receipt` → `ending`

状态必须保留报表所用的真实对话和账本。镜头冲突过场只影响视觉，不可以凭空给身体打风险分或给劳动者记一笔不存在的分成。

### 5.3 文字层级与呼吸感

默认一屏一个主任务；对白主要以人类日常语感出现；屏幕高度不足时把解释收进报告内滚动，不允许情绪大字长时间压在表单上。主字幕 4–10 个汉字，副字幕只解释一个因果；报告首先用两句人话讲“发生了什么”和“为什么值得问”。详细学术解释放入展开项，不与玩家的动作竞争注意力。

### 5.4 各尺度实测

桌面 1440×900 需要保留人物与主要交互目标视觉区域；移动 390×844 必须保证报告标题、首句和对照逻辑无需横向滚动，关键行动按钮能完整点击。点击后要有明确的成败反馈，不能以单纯“下一页”代替结果。

## 6. 3D 空间生产与插件门禁

当前使用程序化三维房间/人物与软件投影回退；本次主要提高视觉叙事，**未生成付费 Meshy 模型、未完成 Blender 高精度房间、未新增布料或血液流体动力学**。依据 3D Gameplay Room 门禁，将下一阶段所需的生产资料明确如下：

- **Function Gate（待人工批准）：** 三幕各提交1个空间审查包，明确摄像机、主交互物、可行走边界、碰撞与安全恢复区域；确认每个通道指向真实可进入的目的地，预留人物完整动作包围盒。避免屏幕重要目标与装饰遮挡。
- **Form Gate（待人工批准）：** 结构壳体、平台地面、采集工作台、控制台、门洞与结构支撑的实际几何；按真实镜头检查人物脚底接触、道具支撑、立面、阴影和屏幕空间切线；必须通过指定平面/角落/天花板审查。未经批准不可宣称精细模型已完成。
- **Runtime Gate（待人工批准）：** 从真实生产视角检查加载后相机、动态材质、纹理分级、帧率、碰撞、交互和表演；不能用概念截图代替实机验收。
- **暂不进行的项目：** 付费 Meshy 提交（无用户批准）、无真实动作数据的“真实人体运动捕捉”宣称、医学意义的疼痛/血液物理模拟。

## 7. 已实现内容 / 验证边界 / 下一轮任务

2. 三次冲突的镜头层与色彩状态（资料门槛、转写遗漏、数据复用），以及十次采集结束时的岗位终止提示。
3. 冲突特写与报告分时展示，避免大字遮挡证据。
4. 第一幕追加角色现实内的成本选择及记录。
5. 第二幕原话—错误转写—留存文本的删除/恢复对照。
6. 第三幕首次调用的身体与收入因果强调。
7. 最终结局改写为三枚证据物的统一解释，不把用户突然写成医院/平台管理员。
8. 原有 WebGL/CPU 软件投影、问诊聊天与第三幕交易规则仍保留。

### 需继续制作（不能伪称完成）

- 整个电影空间的定制材质和高精度角色资产，逐帧脚步 IK、抓举负重和触屏动作，专业电影混音、真实刚体与布料模拟。
- 更完整的第一幕后续场景（真的去找工作/请假/等待）、第二幕转诊旅程（交通、预约及复诊）、第三幕跨地区许可谈判事件。
- 智能对话可控生成与医学安全边界；目前是本地剧情树与关键词识别，不是开放式医疗 AI。
- 正式无障碍审计、不同 CPU/GPU/移动设备的性能基线和真实新手盲测。

## 9. 只看结尾能回答什么

玩完《肉身审计局》应该不再只是说“AI有偏见”，而能说出三件具体的事：

> **第一，人的旧档案被用成了服务门槛。第二，人说出口的话可能在转换为数据时被抹掉。第三，一份身体劳动记录会离开采集者，变成另一个人反复使用和获益的资源。问题不只是机器会不会计算，而是谁有权规定这些计算如何作用于人的生活。**

这段话是游戏的终极学习收获；任何镜头、对白、交互和资产如果不帮助它成立，就不应继续堆叠。
